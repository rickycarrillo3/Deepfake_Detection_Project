# models/DMimageDetection/

Shared clone + weights + environment for both Grag2021 variants from
[grip-unina/DMimageDetection](https://github.com/grip-unina/DMimageDetection)
(ICASSP 2023 — "On the Detection of Synthetic Images Generated by
Diffusion Models"). Both are the same `res50stride1` architecture,
differing only in training data — `Grag2021_progan` (ProGAN outputs) and
`Grag2021_latent` (latent-diffusion outputs) — and both ship in the same
weights zip, so they share one clone/env/download here instead of each
duplicating it.

```
DMimageDetection/
├── dmimagedetection/          # vendored clone (shared)
├── venv/      # shared venv
├── weights/
│   ├── Grag2021_progan/model_epoch_best.pth
│   └── Grag2021_latent/model_epoch_best.pth
├── setup.sh                   # sets up everything above, once
├── requirements.txt           # shared deps
├── DMimageDetection_GAN/
│   ├── model.py                # load()/predict() contract
│   └── predict_one.py          # single-image CLI
└── DMimageDetection_DM/
    ├── model.py
    └── predict_one.py
```

See each subfolder's `model.py` docstring for architecture/preprocessing
details (fully-convolutional ResNet-50, no resize/crop, spatial-logit
averaging, sigmoid → probability). Nothing about the actual detection
logic differs from having two fully separate folders — this is purely
about not cloning the repo and downloading ~500MB of weights twice.

## Setup (once, for both variants)

```bash
cd models/DMimageDetection
bash setup.sh
```

If you've already downloaded `weights/` manually (matching the layout
above), `setup.sh` detects both `.pth` files and skips the download step.

## Running each variant

Each variant is run independently and writes its own `results/` output. Run from
the repo root, using the shared venv — each variant is its own `--model`:

```bash
models/DMimageDetection/venv/bin/python run.py --model DMimageDetection_GAN --dataset <dataset_name>
models/DMimageDetection/venv/bin/python run.py --model DMimageDetection_DM  --dataset <dataset_name>
```

Each `result_stem()` is just the registry name — it already carries the family — so the runs write
`results/<dataset_name>_DMimageDetection_GAN_predictions.csv` and
`..._DMimageDetection_DM_predictions.csv`. Schema in
[`results/README.md`](../../results/README.md).

Both run the fully-convolutional ResNet-50 at **native resolution** (no resize, no crop), so their
cost scales with pixel count — a 1024² image is ~21× the pixels of 224², which is why they feel
heavy for a ResNet. That behavior is load-bearing, not an oversight: downsampling would destroy
the high-frequency cues the method keys on. See [`ResizingRemarks.md`](../../ResizingRemarks.md).

Because both models share one venv and one clone, a sweep cleans that shared directory up **once
at the very end** rather than after either model individually — deleting it after the first would
break the second's run (`SHARED_CLONE_ROOTS` / `SHARED_VENV_ROOTS` in the top-level `run.py`).

Single image from the terminal (either variant):
```bash
cd models/DMimageDetection/DMimageDetection_GAN
../venv/bin/python predict_one.py /path/to/image.png
```

## Why not merge the two into one model.py?

They're kept as separate `model.py` files, registered as two distinct
models in the top-level `run.py` (rather than one model with a variant flag), because they're independent trained
detectors for your correlation/ensembling analysis — you want
`results/` entries for `DMimageDetection_GAN` and `DMimageDetection_DM` as genuinely
separate signals, matching how `main.py` itself treats them as two
entries in its `models_list`.
